WEB DEVELOPMENT PRACTICE

LEARNING BY BUILDING

A line of code becomes exciting when it changes something on screen. That's what keeps me coming back to my computing exercises.

I began with simple webpage structures, then learned to arrange them with CSS and make them respond to clicks and input using JavaScript.

Some lessons arrived through mistakes: a missing file path, an image that expanded too far, or a link that pointed to the wrong page. Fixing those problems helped me understand how the pieces fit together.

THREE TOOLS, THREE DIFFERENT JOBS

HTML gives a webpage meaning and structure: headings, paragraphs, forms, images, and links that connect one page to another.

CSS decides how that structure feels, from spacing and typography to responsive grids, color, and hover interactions.

JavaScript brings behavior to the page by reading values, using functions, doing calculations, and displaying results immediately.

SMALL EXPERIMENTS, REAL RESULTS

In class, I practiced a temperature conversion function a short exercise that showed how a formula becomes something a webpage can display.

My interactive study planner takes the hours and days selected by a user, calculates a daily target, and gives a readable answer.

I also practiced debugging real webpage problems, from oversized photographs to mismatched filenames and project links.

THE DEBUGGING DIARY

When a page did not look right, I learned to inspect the HTML structure first, then check the CSS rule that controlled it. That approach was especially useful for image sizes and section alignment.

Another lesson came from project navigation: a button can look perfect and still lead to the wrong page. Testing each click became part of the development process.

MY NEXT CHALLENGE

I want to make my code cleaner and more reusable, with responsive layouts that feel natural on both a Mac and a phone.

Eventually, I would like to create small web tools that help people plan, learn, or play together—projects with a clear purpose and a little personality.
